[[NGK_SO_FunctionsExt_IsInsideAreaByCode]]
=== IsInsideAreaByCode

[.fn-sig]
.Funktionsname und Signatur (Modell `NGK_SO_FunctionsExt`)
[source]
----
FUNCTION IsInsideAreaByCode(
    Objects: OBJECTS OF ANYCLASS;
    GeometryAttr: TEXT;
    CodeAttr: TEXT
  ): BOOLEAN;
----

*Zweck*

Prüft, ob bei einer Objektmenge die gemäss Code jeweils kleineren Flächen innerhalb der grösseren Flächen liegen.

*Parameter*

[cols="2,6", options="header"]
|===
|Name |Beschreibung
|`Objects` |Zu prüfende Objektmenge.
|`GeometryAttr` |Pfad zur Flächengeometrie.
|`CodeAttr` |Pfad zum Enum- oder numerischen Attribut, nach dem die Flächen sortiert werden.
|===

*Rückgabewert:* `BOOLEAN`

*Beispielaufruf*

[source]
----
SET CONSTRAINT NGK_SO_FunctionsExt.IsInsideAreaByCode(ALL, "Geometrie", "Code");
----

*Skizze und Erläuterung*

.Skizze zu IsInsideAreaByCode
image::NGK_IsInsideAreaByCode.svg[Skizze zu IsInsideAreaByCode,width=90%]

Das Enum muss als `ORDERED` von der kleinsten zur grössten Fläche sortiert sein; bei numerischen Codes gilt die aufsteigende Sortierung. Die Funktion wird oft mit `GeoW_FunctionsExt.GetInGroups` kombiniert, um die Prüfung je Prozessquelle durchzuführen. Seit 2024-01-23.
