[[kap_Text_V2]]
== Text_V2: Textfunktionen

Funktionen zur Bearbeitung und zum Vergleich von Texten aus dem Modell `Text_V2`. Jede Funktion besteht aus einer Variante für `TEXT` und einer Variante mit Suffix `M` für `MTEXT`. Beide werden gemeinsam beschrieben.

[cols="2,8"]
|===
|Modell |`Text_V2`
|Version |2023-05-25
|Quelle |`iox-ili/src/test/data/validator/Text_V2.ili`; Implementierung `ch.interlis.iox_j.validator.functions.Text`
|===

TIP: Positionen werden ab 0 gezählt (wie in Java). Ist ein Argument `UNDEFINED`, wird die Bedingung nicht ausgewertet.

[[Text_V2_compareToIgnoreCase]]
=== compareToIgnoreCase / compareToIgnoreCaseM

[.fn-sig]
.Funktionsname und Signatur (Modell `Text_V2`)
[source]
----
FUNCTION compareToIgnoreCase(a: TEXT; b: TEXT): NUMERIC;

FUNCTION compareToIgnoreCaseM(a: MTEXT; b: MTEXT): NUMERIC;
----

*Zweck*

Vergleicht zwei Texte lexikographisch, ohne Gross-/Kleinschreibung zu beachten.

Die Variante mit Suffix `M` arbeitet identisch, jedoch mit Attributen vom Typ `MTEXT` (mehrzeiliger Text).

*Parameter*

[cols="2,2,6", options="header"]
|===
|Name |Typ |Beschreibung
|`a` |`TEXT` |Erster Text.
|`b` |`TEXT` |Zweiter Text, mit dem verglichen wird.
|===

*Rückgabewert:* `NUMERIC`

*Beispielaufruf*

[source]
----
MANDATORY CONSTRAINT Text_V2.compareToIgnoreCase(NameAlt, NameNeu) == 0;
----

*Skizze und Erläuterung*

.Skizze zu compareToIgnoreCase
....
a = "Bern"   b = "BERN"  ──► 0
a = "Aarau"  b = "Bern"  ──► negativ (a < b)
a = "Zug"    b = "Bern"  ──► positiv (a > b)
....

Resultat: 0 bei Gleichheit, negativ wenn `a` vor `b` einsortiert wird, positiv wenn danach. Ist ein Argument UNDEFINED, wird die Bedingung nicht ausgewertet.

*Skizze und Erläuterung*

....
a = "Bahnhof" ─┐

b = "strasse" ─┘
....

Der zweite Text wird unmittelbar (ohne Trennzeichen) an den ersten angehängt. Ist ein Argument UNDEFINED, wird die Bedingung nicht ausgewertet.

FUNCTION endsWithM(val: MTEXT; suffix: MTEXT): BOOLEAN;
----

*Zweck*

Prüft, ob ein Text mit einem bestimmten Suffix endet.

Die Variante mit Suffix `M` arbeitet identisch, jedoch mit Attributen vom Typ `MTEXT` (mehrzeiliger Text).

*Parameter*

[cols="2,2,6", options="header"]
|===
|Name |Typ |Beschreibung
|`val` |`TEXT` |Zu prüfender Text.
|`suffix` |`TEXT` |Erwartetes Textende.
|===

*Rückgabewert:* `BOOLEAN`

[source]

....

TRUE, wenn `val` auf `suffix` endet (Gross-/Kleinschreibung wird beachtet). Ist ein Argument UNDEFINED, wird die Bedingung nicht ausgewertet.

[[Text_V2_indexOf]]
=== indexOf / indexOfM

[.fn-sig]
.Funktionsname und Signatur (Modell `Text_V2`)
[source]
----
FUNCTION indexOf(val: TEXT; str: TEXT; fromIndex: NUMERIC): NUMERIC;

FUNCTION indexOfM(val: MTEXT; str: MTEXT; fromIndex: NUMERIC): NUMERIC;
----

*Zweck*

Sucht das erste Vorkommen eines Teiltextes und liefert dessen Position.

Die Variante mit Suffix `M` arbeitet identisch, jedoch mit Attributen vom Typ `MTEXT` (mehrzeiliger Text).

*Parameter*

[cols="2,2,6", options="header"]
|===
|Name |Typ |Beschreibung
|`val` |`TEXT` |Text, in dem gesucht wird.
|`str` |`TEXT` |Gesuchter Teiltext.
|`fromIndex` |`NUMERIC` |Position (ab 0), ab welcher die Suche beginnt.
|===

*Rückgabewert:* `NUMERIC`

*Beispielaufruf*

[source]
----
MANDATORY CONSTRAINT Text_V2.indexOf(Bezeichnung, "-", 0) >= 0;
----

*Skizze und Erläuterung*

.Skizze zu indexOf
....
val = "AB-1234-X"
       0123456789
indexOf(val, "-", 0) = 2
indexOf(val, "-", 3) = 7
indexOf(val, "#", 0) = -1
....

Die Zählung beginnt bei 0. Resultat ist −1, wenn der Teiltext nicht gefunden wird. Die Suche beginnt ab `fromIndex`. Ist ein Argument UNDEFINED, wird die Bedingung nicht ausgewertet.

[[Text_V2_matches]]
=== matches / matchesM

[.fn-sig]
.Funktionsname und Signatur (Modell `Text_V2`)
[source]
----
FUNCTION matches(val: TEXT; regex: TEXT): BOOLEAN;

FUNCTION matchesM(val: MTEXT; regex: TEXT): BOOLEAN;
----

*Zweck*

Prüft, ob ein Text vollständig einem regulären Ausdruck entspricht.

Die Variante mit Suffix `M` arbeitet identisch, jedoch mit Attributen vom Typ `MTEXT` (mehrzeiliger Text).

*Parameter*

[cols="2,2,6", options="header"]
|===
|Name |Typ |Beschreibung
|`val` |`TEXT` |Zu prüfender Text (bei `matchesM` MTEXT).
|`regex` |`TEXT` |Regulärer Ausdruck (Java-Syntax). Bei `matchesM` ebenfalls TEXT.
|===

*Rückgabewert:* `BOOLEAN`

*Beispielaufruf*

[source]
----
MANDATORY CONSTRAINT Text_V2.matches(AdditionalNumber, "[0-9]{2}");
----

*Skizze und Erläuterung*

.Skizze zu matches
....
regex = "[0-9]{2}"
"12"  ──► TRUE
"123" ──► FALSE (zu lang)
"1a"  ──► FALSE
....

Es gilt die Syntax der regulären Ausdrücke von Java. Der Ausdruck muss auf den *gesamten* Text passen (nicht nur auf einen Teil). Bei der Variante `matchesM` ist `val` vom Typ MTEXT, `regex` bleibt TEXT. Ist ein Argument UNDEFINED, wird die Bedingung nicht ausgewertet.

[source]

[[Text_V2_substring]]
=== substring / substringM

[.fn-sig]
.Funktionsname und Signatur (Modell `Text_V2`)
[source]
----
FUNCTION substring(val: TEXT; beginIndex: NUMERIC; endIndex: NUMERIC): TEXT;

FUNCTION substringM(val: MTEXT; beginIndex: NUMERIC; endIndex: NUMERIC): MTEXT;
----

*Zweck*

Liefert einen Teiltext zwischen zwei Positionen.

Die Variante mit Suffix `M` arbeitet identisch, jedoch mit Attributen vom Typ `MTEXT` (mehrzeiliger Text).

*Parameter*

[cols="2,2,6", options="header"]
|===
|Name |Typ |Beschreibung
|`val` |`TEXT` |Ausgangstext.
|`beginIndex` |`NUMERIC` |Startposition (ab 0, inklusive).
|`endIndex` |`NUMERIC` |Endposition (exklusive).
|===

*Rückgabewert:* `TEXT`

*Beispielaufruf*

[source]
----
MANDATORY CONSTRAINT Text_V2.substring(EGRID, 0, 2) == "CH";
----

*Skizze und Erläuterung*

.Skizze zu substring
....
val = "CH123456789012"
       0123456789...
substring(val, 0, 2)  = "CH"
substring(val, 2, 12) = "1234567890"
substring(val, 12, 14) = "12"
....

Die Zählung beginnt bei 0; `beginIndex` ist inklusive, `endIndex` exklusiv. Ohne `endIndex` wird bis zum Textende kopiert. Ist ein Argument UNDEFINED, wird die Bedingung nicht ausgewertet.
